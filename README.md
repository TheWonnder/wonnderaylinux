# Wonnderay для Linux

**VPN-клиент на VLESS поверх официального ядра Xray.**

## Что это

Wonnderay подключает машину к **вашему собственному** серверу и пропускает
через него трафик. Своих серверов у приложения нет и не продаётся ничего: вы
даёте ему ссылку `vless://` или адрес подписки, выданный панелью, а оно делает
остальное.

## Возможности

| Что умеет | Подробности |
| --- | --- |
| **Два режима** | **Прокси** поднимает SOCKS5/HTTP на `127.0.0.1` и прописывает их в настройки рабочего стола — **без всяких прав**. **Туннель** создаёт сетевое устройство и меняет таблицу маршрутов; права он спросит, но только в момент подключения и только для туннеля. |
| **Права не поднимаются перезапуском** | Графическое приложение под root плохо само по себе и плохо работает под Wayland. Поэтому `pkexec` запускает **один привилегированный хелпер**, а интерфейс остаётся вашим. Один запрос пароля на подключение. |
| **Обход по приложениям** | Выбранные программы ходят мимо туннеля. Сделано штатными средствами ядра — cgroup v2 как метка, nftables, policy routing, — и ни строчки в kernel space. Программу запускает само приложение: Linux решает маршрут в момент создания сокета, и перенос уже работающей программы починил бы только будущие её соединения. |
| **Подписки и серверы** | Список с пингом, избранное, поиск, сортировка, автообновление у каждой подписки по своему расписанию. |
| **Лучший сервер** | Одна кнопка: гасит туннель, меряет весь список и поднимается на победителе. |
| **Проверка под нагрузкой** | Отдельно от пинга: шестнадцать одновременных запросов через сервер. Сервер может честно показывать 60 мс и терять треть соединений, и в браузере это выглядит как `ERR_SSL_PROTOCOL_ERROR`. |
| **DNS не течёт** | Обычный резолвер указывает на роутер локальной сети, который остаётся достижим мимо туннеля. При работающем `systemd-resolved` серверы привязываются к устройству через `resolvectl`, иначе подменяется `/etc/resolv.conf` — с резервной копией и восстановлением при отключении. |
| **IPv6 на время туннеля закрывается** | Иначе сайт с двойным стеком открылся бы мимо него. |
| **Kill switch** | Таблица nftables, которая ставится **одной транзакцией** в момент падения ядра и снимается при отключении. |
| **Оформление** | Чёрный OLED-фон, обои, акцент из картинки. Русский, английский и муринский. |

## Чего здесь нет, и почему

- **Самообновления.** `electron-updater` умеет заменять AppImage, deb и rpm, а
  не pacman и тарболл. Проверка новой версии работает и ведёт на страницу
  релиза, установка — руками. Приложение говорит это **заранее**, на экране
  обновлений, а не при попытке скачать.
- **Значка в трее на обычном GNOME.** Он появляется, только если в системе
  кто-то занял `org.kde.StatusNotifierWatcher` — у KDE это есть, у GNOME без
  расширения нет. Приложение спрашивает об этом при запуске, и если слушателя
  нет, закрытие окна означает выход, а не исчезновение в никуда.
- **Системного прокси за пределами GNOME и KDE.** Единого «системного прокси»
  в Linux не существует, настройка принадлежит рабочему столу. Нераспознанный
  десктоп сообщается как нераспознанный, а не игнорируется молча. До программ,
  которые читают только `http_proxy` из окружения, это не доходит и дойти не
  может: окружение уже запущенного процесса извне не изменить.
- **Сборок под ARM.** Только x86-64.

## Скачать

Актуальная версия — на вкладке **[Releases](../../releases/latest)**.

| Файл | Что это |
| --- | --- |
| `Wonnderay-<версия>-x64.pacman` | Пакет для Arch и производных: `sudo pacman -U <файл>` |
| `Wonnderay-<версия>-x64.tar.gz` | Распаковать куда угодно и запустить `wonnderay` |

Для режима туннеля нужен работающий **polkit** — на любом обычном рабочем столе
он уже есть. Для kill switch нужен **`nft`**.
