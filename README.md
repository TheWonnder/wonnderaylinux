# Wonnderay для Linux

VPN-клиент на VLESS/Xray. Те же подписки и серверы, что на телефоне и на
Windows, и то же ядро — официальный Xray-core поверх `/dev/net/tun`.

## О приложении

- **Два режима.** «Прокси» поднимает SOCKS5/HTTP на `127.0.0.1` и прописывает
  их в настройки рабочего стола — **без всяких прав**. «Туннель» создаёт
  сетевое устройство и меняет таблицу маршрутов; права он спросит, но только в
  момент подключения и только для туннеля.
- **Права не поднимаются перезапуском.** Графическое приложение под root — это
  плохо само по себе и плохо работает под Wayland, поэтому `pkexec` запускает
  один привилегированный хелпер, а интерфейс остаётся вашим. Один запрос
  пароля на подключение.
- **Проверка под нагрузкой.** Кроме пинга есть отдельная проверка: шестнадцать
  одновременных запросов через сервер. Она отвечает на другой вопрос —
  выдержит ли сервер страницу, а не сколько миллисекунд идёт один запрос.
  Сервер может честно показывать 60 мс и при этом терять треть соединений,
  и в браузере это выглядит как `ERR_SSL_PROTOCOL_ERROR`.
- **DNS не течёт.** Обычный резолвер указывает на роутер локальной сети,
  который остаётся достижим мимо туннеля. При работающем `systemd-resolved`
  серверы привязываются к устройству через `resolvectl`, иначе подменяется
  `/etc/resolv.conf` — с резервной копией и восстановлением при отключении.
- **IPv6 на время туннеля закрывается**, иначе сайт с двойным стеком открылся
  бы мимо него.
- **Kill switch** — таблица nftables, которая ставится одной транзакцией в
  момент падения ядра и снимается при отключении.
- **Маршрутизация.** Обход для локальной сети, для `.ru` и `.рф`, свой список
  доменов напрямую.
- **Протоколы:** VLESS поверх TCP / WS / gRPC / XHTTP, TLS и Reality.
- Русский и английский.

Приложение ничего не имитирует: «Подключено» загорается только после живого
ядра и принятого tun-устройства, счётчики трафика читаются из ядра, а пинг
показывает измеренное значение либо честный прочерк.

## Чего здесь нет, и почему

- **Самообновления.** `electron-updater` умеет заменять AppImage, deb и rpm, а
  не pacman и тарболл. Проверка новой версии работает и ведёт на страницу
  релиза, установка — руками. Приложение говорит это заранее, на экране
  обновлений, а не при попытке скачать.
- **Значка в трее на обычном GNOME.** Он появляется, только если в системе
  кто-то занял `org.kde.StatusNotifierWatcher` — у KDE это есть, у GNOME без
  расширения нет. Приложение спрашивает об этом при запуске, и если слушателя
  нет, закрытие окна означает выход, а не исчезновение в никуда.
- **Системного прокси за пределами GNOME и KDE.** Единого «системного прокси»
  в Linux не существует, настройка принадлежит рабочему столу. Нераспознанный
  десктоп сообщается как нераспознанный, а не игнорируется молча. До программ,
  которые читают только `http_proxy` из окружения, это не доходит и дойти не
  может: окружение уже запущенного процесса извне не изменить.
- **Исключения отдельных приложений из туннеля.** Механизм в Linux есть
  (cgroup, метки пакетов), но это отдельная реализация и отдельный экран, а не
  перенос андроидного списка.
- **Сборок под ARM.** Только x86-64.

## Скачать

Актуальная версия — на вкладке [Releases](../../releases/latest).

| Файл | Что это |
| --- | --- |
| `Wonnderay-<версия>-x64.pacman` | Пакет для Arch и производных: `sudo pacman -U <файл>` |
| `Wonnderay-<версия>-x64.tar.gz` | Распаковать куда угодно и запустить `wonnderay` |

Для режима туннеля нужен работающий polkit — на любом обычном рабочем столе он
уже есть. Для kill switch нужен `nft`.
